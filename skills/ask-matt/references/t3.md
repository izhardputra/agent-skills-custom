# Running the flow in T3

Use these only when T3 tools (`mcp__t3-code__*`) are available. Otherwise do the step yourself. Load deferred T3 tools with ToolSearch before calling them. Call `orchestrator_capabilities` once per thread before the first `delegate_task`; take targets from `~/.claude/workflow/config/models.md`.

## Hands: one child per ticket

- `delegate_task` with `role: "implementation"`, `target` = the "Hands (tickets)" row, and the brief from `references/delegation.md`.
- Git repo → `isolation: "worktree"` (own checkout and branch; nothing touches the user's checkout until merge). Not a git repo (Drive documents) → shared, and give each child its own output file.
- Run children async; start every ready ticket (the frontier) at once, max ~4 in parallel.
- Do not poll. Follow the `next` the tool returns; you are notified when a child finishes.
- A child that reports BLOCKED or NEEDS_CONTEXT: answer it, or re-dispatch once on the escalation target (GPT-6 Astra). Two failures → stop and ask the user.

## Reviewer child (when Codex CLI is not the reviewer)

- `delegate_task` with `role: "review"`, `mode: "wait"`, target from the reviewer rows, brief = diff command or document path + the spec + "report only issues that would make this fail the spec; quote the line".

## Brain handoff (heavy L2–L3)

After `to-tickets` is approved:

1. Write `.work/<feature>/brain-brief.md`: spec path, ticket list with blocking edges, level, approval points, reviewer rule ("Claude reviews at the end"), and "report Decisions & assumptions".
2. `t3_thread_launch` in the same project with `modelSelection` = the "Brain (heavy execution)" row, title `<feature> · Astra brain`, and a first message: "ROLE: brain. Read `.work/<feature>/brain-brief.md` and run `/implement-spec`-style execution with hands per `~/.claude/workflow/config/models.md`. Stop at every approval point in the brief."
3. Tell the user the thread link and what to expect. When it reports done, review here (`code-review` + `receiving-code-review`), then close with Decisions & assumptions.

## Plan mode

For L2–L3 alignment, suggest the user switch the thread to plan mode (or start the spec thread with `interactionMode: "plan"`). No file edits until the plan is approved.

## Project scripts and PRs

- If the project has T3 scripts (`setup` on worktree create, `test` on settle), rely on them and read their output instead of re-running everything.
- Work that goes up as a PR: link it, and ask T3 for a PR Guide so the user reads the tour, not the raw diff.

## Not without an explicit ask

Multi-agent Workflow runs, webhook-triggered or scheduled agents, remote environments, and new top-level threads other than the brain handoff.
